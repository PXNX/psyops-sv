# Newspaper Subscriptions and Analytics

This document describes the newspaper subscription and analytics features added to the platform.

## Features

### 1. Newspaper Subscriptions

Users can now subscribe to newspapers to stay updated on their content.

#### Database Schema

**Table: `newspaper_subscriptions`**

- `id` (INTEGER, PRIMARY KEY) - Unique subscription ID
- `user_id` (TEXT, FOREIGN KEY → accounts.id) - The subscriber
- `newspaper_id` (INTEGER, FOREIGN KEY → newspapers.id) - The newspaper being subscribed to
- `subscribed_at` (TIMESTAMP) - When the subscription was created
- **Unique constraint**: (user_id, newspaper_id) - Users can only subscribe once per newspaper

#### User Interface

**Subscribe/Unsubscribe Button**

- Located on the newspaper page (`/newspaper/[id]`)
- Bell icon button
  - Bell icon (MdiBell) = Subscribe
  - Bell-off icon (MdiBellOff) = Unsubscribe
- Only visible to non-journalists (regular users)
- Uses form actions for subscribe/unsubscribe

#### API Endpoints

**POST `/newspaper/[id]?/subscribe`**

- Creates a subscription for the current user to the specified newspaper
- Returns: `{ success: true }` or `{ error: "..." }`
- Validation: Prevents duplicate subscriptions

**POST `/newspaper/[id]?/unsubscribe`**

- Removes the subscription for the current user from the specified newspaper
- Returns: `{ success: true }`

### 2. Article View Tracking

All article views are tracked for analytics purposes.

#### Database Schema

**Table: `article_views`**

- `id` (INTEGER, PRIMARY KEY) - Unique view record ID
- `article_id` (INTEGER, FOREIGN KEY → articles.id) - The article being viewed
- `user_id` (TEXT, FOREIGN KEY → accounts.id, NULLABLE) - The user who viewed (null for anonymous)
- `viewed_at` (TIMESTAMP) - When the view occurred
- **Indexes**:
  - `idx_article_views_article` on article_id
  - `idx_article_views_viewed_at` on viewed_at

#### Tracking Logic

Views are tracked automatically when:

- A user visits `/posts/[id]`
- The viewer is NOT the article author (authors don't inflate their own view counts)
- Tracked for both authenticated and unauthenticated users

### 3. Newspaper Statistics Dashboard

Newspaper owners and editors can view detailed analytics about their newspaper.

#### Access Control

- **URL**: `/newspaper/[id]/statistics`
- **Permissions**: Only accessible to:
  - Newspaper owners (rank: "owner")
  - Newspaper editors (rank: "editor")
- **403 Error**: Returned if accessed by non-staff

#### Statistics Displayed

**Summary Cards (KPIs)**

1. **Total Subscribers** - Total number of users subscribed to the newspaper
2. **Total Views** - Cumulative views across all articles
3. **Total Likes** - Cumulative likes (upvotes) across all articles

**Charts**

1. **Subscriber Growth (30 Days)**
   - Shows cumulative subscriber count over the last 30 days
   - Grouped by date
   - Horizontal bar chart visualization

2. **Post Views (30 Days)**
   - Shows daily view counts for all articles over the last 30 days
   - Grouped by date
   - Horizontal bar chart visualization

**Recent Articles Performance Table**

- Shows the last 10 published articles
- Columns:
  - Article title (linked to article page)
  - Published date
  - View count
  - Like count
- Ordered by most recent first

#### User Interface

**Navigation**

- Chart/statistics icon button (MdiChartLine) appears in the newspaper action bar
- Only visible to owners and editors

**Design**

- Responsive layout (mobile-friendly)
- Card-based summary metrics
- Two-column chart layout on larger screens
- Consistent color scheme:
  - Blue for subscribers
  - Green for views
  - Pink for likes

## Database Migration

To add these features to an existing database:

```sql
-- Run the migration file
\i docs/migrations/add_newspaper_subscriptions_and_views.sql
```

Or execute:

```sql
-- Create newspaper subscriptions table
CREATE TABLE IF NOT EXISTS newspaper_subscriptions (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    user_id TEXT NOT NULL REFERENCES account(id) ON DELETE CASCADE,
    newspaper_id INTEGER NOT NULL REFERENCES newspapers(id) ON DELETE CASCADE,
    subscribed_at TIMESTAMP NOT NULL DEFAULT NOW(),
    CONSTRAINT unique_user_newspaper_subscription UNIQUE (user_id, newspaper_id)
);

CREATE INDEX IF NOT EXISTS idx_subscription_newspaper ON newspaper_subscriptions(newspaper_id);

-- Create article views table
CREATE TABLE IF NOT EXISTS article_views (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    article_id INTEGER NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
    user_id TEXT REFERENCES account(id) ON DELETE SET NULL,
    viewed_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_article_views_article ON article_views(article_id);
CREATE INDEX IF NOT EXISTS idx_article_views_viewed_at ON article_views(viewed_at);
```

## Implementation Details

### Schema Updates (src/lib/server/schema.ts)

New tables and relations added:

- `newspaperSubscriptions` table
- `articleViews` table
- Relations for both tables
- Updated `newspapersRelations` to include subscriptions
- Updated `articlesRelations` to include views

### Routes Modified

1. **`src/routes/(authenticated)/(dock)/newspaper/[id]/+page.server.ts`**
   - Added subscription status check
   - Added subscribe/unsubscribe actions

2. **`src/routes/(authenticated)/(dock)/newspaper/[id]/+page.svelte`**
   - Added subscribe/unsubscribe button
   - Added statistics link for owners/editors
   - Fixed article links to use `/posts/{id}` instead of `/article/{id}`

3. **`src/routes/(authenticated)/(dock)/posts/[id]/+page.server.ts`**
   - Added automatic view tracking on page load
   - Excludes author views from tracking

### New Routes Created

1. **`src/routes/(authenticated)/(dock)/newspaper/[id]/statistics/+page.server.ts`**
   - Permission checks for owner/editor access
   - Fetches all analytics data
   - Aggregates statistics over 30-day periods

2. **`src/routes/(authenticated)/(dock)/newspaper/[id]/statistics/+page.svelte`**
   - Displays comprehensive analytics dashboard
   - Responsive design with charts and tables
